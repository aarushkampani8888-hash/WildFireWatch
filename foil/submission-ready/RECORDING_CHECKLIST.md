# Recording and upload checklist

## Before recording

- Confirm the correct running build and rehearse the route once.
- Make sure the FIRMS panel loads observations; show their NASA source. If the live service is unavailable, say so and do not present staged points as live NASA observations.
- Use a real submitted report or visibly label any staged photo, coordinates, timestamp, or thermal anomaly.
- Keep model uncertainty, data timestamps, and scenario limitations on screen when relevant.
- Close unrelated tabs and hide terminal windows, passwords, API keys, and `.env` files.
- Prepare a clean map view and test the report form, inbox, evidence review, public-data check, and map decision controls.

## During recording

- Target 3:45–3:58 to leave a margin under the four-minute cap.
- Show both the problem and the working product, not just slides.
- Keep the observation report form and inbox in the walkthrough.
- Avoid claiming that thermal anomalies prove fire, the detector gives fire probabilities, or the spread scenario is a real forecast.
- Do not describe a plotted point as a measured fire perimeter or the report location as ignition.
- If a control fails, skip it and describe it accurately; do not edit in a success state that did not happen.

## Before submitting

- Publish the video publicly (for example, YouTube) and test the link in a private/incognito window.
- Confirm the final runtime is between 2 and 4 minutes.
- Add the video URL and public GitHub repository URL to Devpost.
- Select **AI + Climate**.
- List every team member; disclose AI coding assistance; check current eligibility and rules.
- Verify the public repo has the latest source and a clear setup README. Never publish `.env`, operator passwords, local SQLite reports, or private credentials.
- Optionally add `architecture.svg` and fresh UI screenshots to the Devpost gallery.
